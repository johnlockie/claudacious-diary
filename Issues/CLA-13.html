I'd like to add a feature for each blog post. Can we add a "read this to me" play button at the top of each post? And what sort of voices can we go with?

What was done

  • Added a ▶ Read this to me button at the top of every diary entry in index.html (all 13 entries now, plus any added later). It reads the entry's title, body and mood line aloud. The date line is skipped. While it reads, the button changes to ■ Stop reading and the paragraph being read is highlighted.
  • Next to the button is a voice picker that lists the English voices on the reader's device (or every voice, if the device has no English ones). The choice is shared by all posts and saved in localStorage (diary-voice), the same way the theme choice is saved. If you change the voice while a post is playing, the post restarts in the new voice.
  • Only one post plays at a time. Starting a second post stops the first one, and speech stops when the page is closed or reloaded.
  • The speech comes from the browser's built-in Web Speech API (speechSynthesis). The site is a single static file on GitHub Pages with no server, and this is the only option that needs no backend, no API key and no cost. If a browser can't speak, the controls aren't shown at all, so nobody gets a button that does nothing.
  • Text is sent to the speech engine a few sentences at a time (220 characters or fewer per piece). This works around a known Chrome bug where long speech requests stop after about 15 seconds.
  • The controls are styled for all four themes: Hand-written and Typewriter use each theme's accent ink, Doogie Howser gets inverse-video DOS buttons, and Hot Dog Stand gets square white buttons with a black frame.
  • Added this record, Issues/CLA-13.html.

"What sort of voices can we go with?"

There are two kinds. This change ships the first one. The second one is a separate decision for you.

1. Built-in device voices (shipped now)

These are free and private, because the text never leaves the reader's device. Which voices are available depends on the reader's device and browser:

PlatformTypical voices
Chrome (desktop)"Google US English", "Google UK English Female/Male", plus the operating system's voices
Microsoft EdgeMicrosoft "Natural" online voices (e.g. Aria, Guy, Jenny). These are some of the best free voices available.
macOS / iOS SafariSamantha, Daniel, Karen, Moira and others, plus any Enhanced/Premium voices the user has downloaded
WindowsMicrosoft David, Zira, Mark
AndroidGoogle text-to-speech voices installed on the phone

The downside: we can't pick one consistent "Claudacious voice" for every reader, and quality ranges from very good (Edge, Apple Premium) to robotic (older Windows voices).

2. A hosted AI voice (not done, needs your decision)

If you want one recognisable, natural-sounding voice for everyone, use a cloud text-to-speech service. Options include ElevenLabs (most expressive, can design a custom character voice), OpenAI TTS, Google Cloud Text-to-Speech, Azure AI Speech and Amazon Polly. Every one of them needs an API key and costs money per character. Because this site has no server, the practical setup is to pre-generate one MP3 per post when a post is written, commit it next to index.html, and have the same play button play that file. That keeps the API key out of the public page. The device voice can stay as the fallback. Tell us the provider and voice you want, and that can be a follow-up ticket.
